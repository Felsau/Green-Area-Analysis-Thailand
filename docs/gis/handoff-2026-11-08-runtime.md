## 1. ขอบเขตของเอกสารฉบับนี้

เอกสารนี้ครอบคลุม **เฉพาะงานของสัปดาห์ที่ 9 ถึง 13 พฤศจิกายน 2569** เท่านั้น

งานในระบบ GIS ยังมีอีกหลายส่วน แต่ยังไม่ส่งมอบในรอบนี้ เนื่องจากต้องรอผลของงาน
ด้านล่างก่อน จึงจะวางแผนส่วนที่เหลือได้อย่างถูกต้อง

**ขอความร่วมมือ: กรุณาทำเฉพาะสามรายการนี้ และยังไม่ต้องเริ่มงานส่วนอื่น** หากทำล่วงหน้า
ไปก่อนโดยยังไม่ทราบคำตอบของข้อ 1 มีความเป็นไปได้สูงที่จะต้องรื้อทำใหม่

## 3. รายละเอียดงาน

### W1. ตรวจสอบความพร้อมของฐานข้อมูล Supabase

**สิ่งที่ต้องทำ** เปิดแดชบอร์ดของโครงการบน Supabase แล้วตอบสองคำถาม

1. ฐานข้อมูลเป็น PostgreSQL รุ่น 17 ขึ้นไปหรือไม่
2. บัญชีที่ใช้งานมีสิทธิ์สร้าง role (คำสั่ง `CREATE ROLE`) หรือไม่

**เหตุผล** สคริปต์ติดตั้งฐานข้อมูล `migrations/027_gis_foundation.sql` กำหนดเงื่อนไขไว้ว่า
`server_version_num >= 170000` หากรุ่นต่ำกว่านี้ จะติดตั้งไม่ได้ทั้งชุด และแผนงานส่วนที่
เหลือทั้งหมดต้องทบทวนใหม่ ส่วนคำสั่ง `CREATE ROLE` ปรากฏอยู่ใน migration หมายเลข
027 และ 043 ถึง 047 สำหรับสร้าง `gis_owner`, `gis_worker`, `gis_native_worker`
และ `authenticator`

**สิ่งที่ต้องส่ง** คำตอบสองข้อ ใช่หรือไม่ใช่ พร้อมภาพหน้าจอประกอบ

**เกณฑ์ว่าเสร็จ** ทีมทราบคำตอบทั้งสองข้ออย่างชัดเจน

> **ยังไม่ต้องติดตั้ง migration และยังไม่ต้องแก้ไขฐานข้อมูลใด ๆ ในสัปดาห์นี้**

---

### W2. บันทึกค่า digest ของ container image ลงคลังโค้ด

**สิ่งที่ต้องทำ** รับค่า digest จากผู้พัฒนาเดิม (ดูเอกสารฉบับที่ 2 รายการ W3) แล้วสร้าง
ไฟล์ `dev/gis_local/images.json` บันทึกค่าทั้ง 6 รายการ จากนั้น commit เข้าคลังโค้ด

| รายการ | ใช้ที่ไหน |
|---|---|
| `GIS_LOCAL_DB_IMAGE` | `dev/gis_local/compose.yaml` |
| `GIS_LOCAL_AUTH_IMAGE` | `dev/gis_local/compose.yaml` |
| `GIS_LOCAL_REST_IMAGE` | `dev/gis_local/compose.yaml` |
| `GIS_LOCAL_GATEWAY_IMAGE` | `dev/gis_local/compose.yaml` |
| `WORKER_IMAGE` | `dev/gis_local/manage.py` บรรทัดที่ 47 |
| `GEE_MOCK_WORKER_IMAGE` | `dev/gis_local/manage.py` บรรทัดที่ 48 |

**เหตุผล** ปัจจุบันค่าเหล่านี้ไม่มีบันทึกอยู่ในคลังโค้ด ผลการตรวจสอบบนเครื่องผู้จัดทำเอกสาร

```
$ docker image inspect sha256:fca4560d8a0d...aa04c9
NOT ON THIS MACHINE
$ docker image inspect sha256:7557955c9e2c...9566674
NOT ON THIS MACHINE
```

และไฟล์ `compose.yaml` กำหนดไว้แบบบังคับโดยไม่มีค่าเริ่มต้น

```
image: ${GIS_LOCAL_DB_IMAGE:?pinned image required}
```

เท่ากับว่าขณะนี้มีเพียงเครื่องของผู้พัฒนาเดิมเพียงเครื่องเดียวที่ประกอบระบบขึ้นมาได้ หาก
เครื่องนั้นเสียหาย จะไม่มีวิธีสร้างสภาพแวดล้อมเดิมขึ้นใหม่

**สิ่งที่ต้องส่ง** ไฟล์ `dev/gis_local/images.json` ที่ commit แล้ว

**เกณฑ์ว่าเสร็จ** ผู้อื่นสามารถสั่ง `docker compose up` ได้สำเร็จโดยไม่ต้องสอบถามผู้ใด

> **ยังไม่ต้องสร้าง Dockerfile และยังไม่ต้องแก้ไขสคริปต์ใด ๆ ในสัปดาห์นี้**

---

### W5. สร้าง Dockerfile ของ worker

**สิ่งที่ต้องทำ** สร้างไฟล์ `green-area-backend/gis_worker/Dockerfile` แล้ว build เป็น
image จากนั้นรันชุดทดสอบ native ภายใน image นั้นโดยตั้ง `GIS_NATIVE_RUNTIME=pinned`

สูตรต่อไปนี้ผ่านการทดสอบแล้ว ใช้เป็นจุดตั้งต้นได้

```
FROM python:3.11-slim
RUN apt-get update && apt-get install -y --no-install-recommends libexpat1     && rm -rf /var/lib/apt/lists/*
COPY requirements-native.txt .
RUN pip install --no-cache-dir -r requirements-native.txt
ENV GIS_NATIVE_RUNTIME=pinned
```

**เหตุผล** ชุดทดสอบ `test_v1_artifacts_of_existing_fixtures_are_byte_identical`
ตรวจว่าผลลัพธ์จากการแปลง shapefile ตรงกับค่าที่ตรึงไว้ทุกไบต์ ผลการทดลองพบว่า
ไลบรารีรุ่นเดียวกันให้ผลต่างกันตามเครื่อง

| สภาพแวดล้อม | ผล |
|---|---|
| `python:3.12-slim` ใน Docker | ผ่าน |
| เครื่อง GitHub `ubuntu-24.04` (wheel ไฟล์เดียวกัน) | ไม่ผ่าน |
| Windows 11 | ไม่ผ่าน |

การตรึงรุ่นไลบรารีจึงยังไม่พอ ต้องตรึงทั้ง image ปัจจุบันชุดทดสอบนี้ถูกข้ามอัตโนมัติ
และจะทำงานก็ต่อเมื่อมี image ที่ตรึงไว้แล้วเท่านั้น

**สิ่งที่ต้องส่ง** ไฟล์ `Dockerfile` คำสั่ง build และผลการรันชุดทดสอบ

**เกณฑ์ว่าเสร็จ** รัน `pytest tests/test_ldd_policy_native.py` ภายใน image แล้วผ่าน
ครบทุกข้อ **รวมถึงข้อที่ปกติถูกข้าม** หากข้อนั้นยังไม่ผ่าน แปลว่า image ยังไม่ตรง

> **งานนี้ไม่ต้องรอคำตอบของ W1 หรือ W3** เริ่มได้ทันที เพราะใช้เพียง base image
> สาธารณะกับไฟล์ `requirements-native.txt` ที่มีอยู่แล้ว
>
> **ยังไม่ต้องนำ image ไปผูกกับ `dev/gis_local/manage.py` และยังไม่ต้องอัปขึ้น
> registry ใด ๆ** ขอแค่พิสูจน์ว่า image สร้างผลลัพธ์ตรงกับที่ตรึงไว้

## 4. งานที่ยังไม่ส่งมอบในรอบนี้

รายการต่อไปนี้อยู่ในแผนระยะถัดไป **กรุณายังไม่เริ่มดำเนินการ**

1. การเขียนตัวติดตั้ง migration สำหรับฐานข้อมูลบนคลาวด์
2. การย้ายที่จัดเก็บไฟล์ที่ผู้ใช้อัปโหลด

ทั้งสองรายการขึ้นอยู่กับคำตอบของงาน W1 และ W2 โดยตรง จะส่งมอบในรอบถัดไป

## 5. สิ่งที่จัดเตรียมไว้ให้แล้ว

1. ระบบตรวจอัตโนมัติ (CI) ทำงานได้และผ่านทุกขั้นตอนแล้ว หากเปิด pull request
   แล้วขึ้นสถานะไม่ผ่าน แสดงว่าเป็นสิ่งที่เพิ่งแก้เข้าไป ไม่ใช่ปัญหาเดิมที่ค้างอยู่
2. ไฟล์ `green-area-backend/requirements-native.txt` ระบุรุ่นไลบรารีที่ตรวจสอบแล้ว
3. ไฟล์ตัวอย่างการตั้งค่าอยู่ที่ `green-area-backend/.env.example` และ
   `green-area-frontend/.env.example`

## 7. ภาคผนวก ภาพหลักฐาน

ในไฟล์ `.docx` มีกรอบสำหรับวางภาพหน้าจอไว้ให้แล้ว กรอบใดไม่มีภาพให้เขียนเหตุผลกำกับไว้แทน

| ภาพที่ | เรื่อง | ในภาพต้องเห็น |
|---|---|---|
| 1 | รุ่นของฐานข้อมูล (งาน W1) | หน้าแดชบอร์ด Supabase ส่วนที่ระบุรุ่น PostgreSQL โดยเห็นชื่อโครงการประกอบด้วย |
