## 1. ขอบเขตของเอกสารฉบับนี้

เอกสารนี้ครอบคลุม **เฉพาะงานของสัปดาห์ที่ 9 ถึง 15 พฤศจิกายน 2569** เท่านั้น

ยังมีเรื่องที่ต้องตัดสินใจอีกหลายข้อในระบบ GIS แต่ยังไม่ส่งมอบในรอบนี้

## 2. สิ่งที่เปลี่ยนแปลงไปแล้ว และกระทบท่านอย่างไร

ระหว่างวันที่ 7 ถึง 8 พฤศจิกายน 2569 มีการต่อยอดงานบนบรานช์
`feature/gis-data-management` เพื่อให้ระบบติดตั้งลงฐานข้อมูลที่ไม่ใช่ sandbox ในเครื่องได้
รวม 9 commit บนบรานช์ใหม่ชื่อ `gis-unlock`

พฤติกรรมเดิมของ sandbox ถูกรักษาไว้ครบถ้วน และ **ไม่ต้องแก้ไขสคริปต์ในโฟลเดอร์ `dev`
แม้แต่ไฟล์เดียว** แต่มีผลข้างเคียงหนึ่งรายการที่ต้องดำเนินการ

**ผลข้างเคียง** `migrations/027_gis_foundation.sql` ถูกแก้ไข ทำให้ค่า checksum ที่ตรึง
ต่อกันเป็นลูกโซ่ต้องคำนวณใหม่ ตั้งแต่หมายเลข 027 จนถึง 048 ตาราง
`gis.schema_migrations` ใน sandbox T0 เดิมจึงไม่ตรงกับไฟล์ปัจจุบันอีกต่อไป

ตรวจสอบรายการที่เปลี่ยนแปลงได้ด้วยคำสั่ง

```
git diff b9b5b3a HEAD -- green-area-backend/migrations
```

**เหตุผลที่ต้องแก้** `cluster_name` เป็นค่าตั้งระดับ postmaster ซึ่งบริการแบบ Supabase
Cloud กำหนดไม่ได้ เมื่อนำ migration 027 ฉบับเดิมไปติดตั้งบน PostgreSQL 17 มาตรฐาน
จะได้ผลดังนี้

```
ERROR: GIS_LOCAL_TARGET_REQUIRED
```

หลังแก้ไข ตัวติดตั้งจะประกาศค่า `gis.cluster_name` และ `gis.mode` เอง โดย **การไม่
ประกาศค่ายังคงหมายถึง sandbox เหมือนเดิมทุกประการ**

## 4. รายละเอียดงาน

### W3 — ส่งค่า digest ของ container image ทั้ง 6 รายการ

**สิ่งที่ต้องทำ** ส่งค่า digest ที่ใช้งานอยู่จริงบนเครื่องของท่าน

| ตัวแปร | ที่มา |
|---|---|
| `GIS_LOCAL_DB_IMAGE` | `dev/gis_local/compose.yaml` |
| `GIS_LOCAL_AUTH_IMAGE` | `dev/gis_local/compose.yaml` |
| `GIS_LOCAL_REST_IMAGE` | `dev/gis_local/compose.yaml` |
| `GIS_LOCAL_GATEWAY_IMAGE` | `dev/gis_local/compose.yaml` |
| `WORKER_IMAGE` | `dev/gis_local/manage.py` บรรทัดที่ 47 |
| `GEE_MOCK_WORKER_IMAGE` | `dev/gis_local/manage.py` บรรทัดที่ 48 |

**เหตุผล** ค่าทั้งหมดไม่มีบันทึกอยู่ในคลังโค้ด จากการตรวจสอบบนเครื่องของผู้จัดทำเอกสาร
พบว่า image ทั้งสองรายการของ worker ไม่มีอยู่ และค้นทั้งคลังโค้ดแล้วไม่พบค่าของตัวแปร
ทั้งสี่รายการแรก ขณะนี้จึงมีเพียงเครื่องของท่านเพียงเครื่องเดียวที่ประกอบระบบขึ้นมาได้

**สิ่งที่ต้องส่ง** ค่า digest ทั้ง 6 รายการ ส่งเป็นข้อความได้

**เกณฑ์ว่าเสร็จ** ผู้รับผิดชอบงาน W2 นำไปบันทึกลงคลังโค้ดได้

> นี่คืองานที่เร่งด่วนที่สุดในสัปดาห์นี้ เนื่องจากหากเครื่องของท่านเสียหายก่อนส่งมอบ
> จะไม่มีวิธีสร้างสภาพแวดล้อมเดิมขึ้นใหม่ได้เลย

---

### W4 — สร้าง sandbox T0 ขึ้นใหม่

**สิ่งที่ต้องทำ** ดึงบรานช์ `gis-unlock` มาแล้วสร้าง T0 ขึ้นใหม่ตามขั้นตอนเดิมของท่าน

**เหตุผล** ตามข้อ 2 ค่า checksum ถูกคำนวณใหม่ ledger เดิมจึงไม่ตรงกับไฟล์ปัจจุบัน
**โค้ดและสคริปต์ของท่านไม่ต้องแก้ไข กระทบเฉพาะฐานข้อมูลเท่านั้น**

**สิ่งที่ต้องส่ง** ผลการรันที่ยืนยันว่า `gis_readiness()` รายงานค่าถูกต้อง

**เกณฑ์ว่าเสร็จ** ชุดทดสอบบนเครื่องของท่านผ่านครบ

---

### W6 — ตรวจทานการแก้ไขด่านความปลอดภัยใน migration 027

**สิ่งที่ต้องทำ** ตรวจทานการแก้ไขด่านตรวจเป้าหมายใน `migrations/027_gis_foundation.sql`
และฟังก์ชันใหม่ `gis.target_ok()` ว่ายังรักษาหลักประกันเดิมที่ท่านออกแบบไว้ครบถ้วนหรือไม่

```
git diff b9b5b3a HEAD -- green-area-backend/migrations/027_gis_foundation.sql
```

**เหตุผล** ด่านนี้เป็นส่วนที่กันไม่ให้ระบบไปแตะฐานข้อมูลที่ไม่ได้ประกาศไว้ ซึ่งท่านเป็น
ผู้ออกแบบ การแก้ไขครั้งนี้ยังไม่มีผู้ใดตรวจทานอย่างเป็นอิสระ

ระหว่างการพัฒนาเคยเกิดข้อผิดพลาดขึ้นจริงหนึ่งครั้ง คือเมื่อกำหนดค่าปริยายให้เฉพาะฝั่ง
sandbox ทำให้เงื่อนไขฝั่ง cloud กลายเป็น NULL ส่งผลให้ทั้งนิพจน์เป็น NULL และคำสั่ง
`IF` ไม่ทำงาน ด่านจึงเปิดโล่งโดยไม่มีสัญญาณเตือน ข้อผิดพลาดนี้ถูกพบและแก้ไขแล้วด้วยการ
ใช้ `COALESCE` ทั้งสองฝั่ง แต่แสดงให้เห็นว่าโค้ดส่วนนี้ผิดพลาดได้โดยไม่มีอาการ

**สิ่งที่ต้องส่ง** ข้อความยืนยันว่าตรวจแล้วรับได้ หรือรายการข้อทักท้วงพร้อมเหตุผล

**เกณฑ์ว่าเสร็จ** มีคำตอบเป็นลายลักษณ์อักษร

**ผลการทดสอบที่ทำไว้แล้ว** ทดสอบบน container PostgreSQL 17 จำนวน 5 กรณี

| กรณีทดสอบ | ผลลัพธ์ |
|---|---|
| ไม่ประกาศค่าใด และ postmaster ไม่ใช่ sandbox | ปฏิเสธ |
| ประกาศ sandbox แต่ postmaster ไม่ใช่ sandbox | ปฏิเสธ |
| ประกาศ project ref แต่ mode เป็น local | ปฏิเสธ |
| ไม่ประกาศค่าใด และ postmaster เป็น sandbox (ทางเดิม) | ติดตั้งครบ 027 ถึง 048 |
| ประกาศ cloud และไม่มี cluster_name | ติดตั้งครบ 027 ถึง 048 |

> ขอให้ตรวจทานในมุมของผู้ออกแบบว่ามีกรณีใดที่ยังไม่ได้ทดสอบหรือไม่

## 5. งานที่ยังไม่ส่งมอบในรอบนี้

รายการต่อไปนี้ต้องตัดสินใจร่วมกันก่อน **กรุณายังไม่เริ่มดำเนินการ** และจะนัดหารือ
ในรอบถัดไป

- การรวม commit `78f0219` เข้ากับบรานช์ และการพิจารณาขอบเขตของ `legacy-v1`
- การพิจารณาว่า worker ใดควรทำงานบนคลาวด์
- การกำหนดเงื่อนไขการอนุมัติประมวลผล Google Earth Engine จริง

> **ข้อควรระวังหากเผลอเริ่มก่อน** ค่า hash ที่ตรึงไว้ในขณะนี้ยังตรงกับไฟล์บนบรานช์
> การปรับค่า hash ก่อนการรวมบรานช์จะทำให้ชุดทดสอบไม่ผ่านโดยไม่จำเป็น
