# A1 — Local GIS Publication Foundation

Contract `1.0.0-a1`. SQL migration `037_gis_publication_foundation.sql` adds a
foundation only: **no prepare processing, trusted artifact verifier, activation,
withdrawal, rollback execution, Dashboard reader change or live GEE**.

## Source and scope

- Reuse Dataset identity `(province,data_year,month,kind,purpose)` and the existing
  `active_edition_id`; do not introduce a second active pointer or district key.
- Publication scope starts at province level. Month0 is annual,1–12 monthly;
  LDD remains annual. An annual source cannot silently stand for a month.
- `gis_publication.SourceIdentity` separates `legacy` from `published`, binding
  product/province/year/month/method and, for Published, Dataset/Edition/current
  validation Result/input hash/source SHA256. Its deterministic cache namespace
  is a future-reader contract; no existing Cache reader uses it in A1.
- A Published namespace is descriptive provenance, **not proof of publication**.
  Readiness, active pointer and authorization must still be checked by future readers.
- No arbitrary URLs, SQL, commands or filesystem paths belong in registrations.

## Validation versus readiness

1. Uploaded: immutable source association and SHA256 exist.
2. Validation valid: exact successful native Job/Attempt/Result agrees with the
   current Edition hash/revision and original upload. Synthetic/Offline results
   cannot qualify as real input. LDD uses its validated Edition/result pointer;
   GeoTIFF deliberately remains draft and uses its successful validation report.
3. Artifact registered: immutable **declaration** of a future prepared output,
   bound to that validation lineage. Hash/size/coverage are not verified file I/O.
4. Ready: **not available in A1**. `verification_available`, `coverage_verified`
   and `ready_for_publication` always false; `gis.publication_ready` fails closed.

`publication_status(edition,method)` reports `validation_required`,
`artifacts_required` or `registered_unverified`, plus completeness and missing
roles. Artifacts from different methods are never combined to claim completeness.
GeoTIFF province/year/coverage validation is not implicitly upgraded by A1.

## Registry

`gis.publication_artifacts` references Dataset/Edition/Validation Result through
foreign keys and checks current native result/job/attempt lineage on insert.
It records input revision/hash, original SHA256, declared artifact SHA256/size,
method version, province scope and nullable registering actor.

- LDD roles: `ldd_geometry`, `ldd_summary`.
- NDVI roles: `ndvi_raster`, `ndvi_summary`.
- LST roles: `lst_raster`, `lst_summary`.
- Each `(edition,artifact_kind,method_version)` is unique. Correcting a registered
  declaration requires a new method version or new Edition, never overwriting it.
- Each declared artifact is bounded to20MiB, matching current local input limits.
  This is not evidence that a prepared provincial artifact can fit or be processed.
- Logical `object_key = sha256/<artifact_sha256>/<artifact_kind>` is generated by
  SQL; it is not a filesystem locator or permission to read a file.
- Rows cannot be updated/deleted. Account deletion may only null `registered_by`
  through its FK action; source references, hashes and Audit remain intact.

## Authorization and SQL interface

Private schema owner: existing NOLOGIN `gis_owner`, FORCE RLS, owner-only policy.
Browser roles, service role and both worker roles have no direct table access.

Service-only public RPC wrappers (no new HTTP routes in A1):

- `gis_publication_register(actor,request_id,payload)`: Admin only. Backend must
  supply actor from its existing verified JWT context, never a request-body actor.
- `gis_publication_read(actor,edition,method)`: existing GIS Officer/Admin catalog
  authorization. It exposes metadata, never native diagnostics or credentials.

Register payload: `edition_id`, `expected_dataset_revision`,
`expected_input_revision`, `input_hash`, `validation_result_id`, `source_sha256`,
`artifact_kind`, `artifact_sha256`, `byte_size`, `method_version`, `reason`.
Extra fields, self-asserted readiness/coverage and arbitrary locators are rejected.

Lock order: actor authorization → request receipt → Dataset → Edition → registry.
Authorization is rechecked after waiting. Exact request replay returns the stored
receipt; changed payload gives conflict. Registry+Audit+receipt commit atomically.
Registration does not change Dataset revision, Edition state or active pointer.

## Activation, withdrawal and rollback

Existing Admin checks, dual gates, revision/pointer CAS, receipt, locks and Audit
remain unchanged. Existing validation eligibility/deferred triggers are preserved.
New `publication_pointer_guard` rejects a change to a non-null active Edition
unless `publication_ready` permits it; in A1 it never does. This also covers
future rollback/replacement paths and direct owner updates, not only one RPC.
The existing immutable-row/gate trigger executes first. No gate is enabled.

Future semantics: superseding an Edition keeps the previous Edition and artifacts
for rollback; withdrawn is terminal and requires a new clone/revalidation for
reuse. A future withdrawal may choose a ready replacement or explicitly clear the
pointer. A1 neither runs these actions nor deletes sources/history.

## Requirements for A2/A4 (not implemented here)

Trusted verifier must inspect actual immutable artifact bytes/hash/size, province
footprint/completeness, period/provenance and method-specific outputs, tied to
fenced worker identity and the current input/result. Native process gets no DB
credentials. Preparation uses the existing Queue/Worker/Storage boundaries.
Future forward SQL must enable verified readiness without accepting an Admin's
boolean assertion, mixing methods or weakening old validation invariants.

Only after candidate verification may an approved transaction switch the existing
pointer. Derived results/Cache must remain versioned separately from Legacy;
failure before commit keeps the previous source. This work belongs to A2–A6.

## Local checks

Use the existing attested runtime outside the Repository. No `.env` or credentials
are read by the A1 runner; no containers are started or created.

```text
python -I -B dev/gis_local/publication_local.py proof --runtime-dir <existing-runtime>
python -I -B dev/gis_local/publication_local.py migrate --runtime-dir <existing-runtime> --review dev/gis_local/publication-review.json
python -I -B dev/gis_local/publication_checks.py --runtime-dir <existing-runtime>
```

Migration requires exact independent-review SHA256 and a closed-gate local036
baseline. Applied037 is never replayed; mismatch fails before mutation, including
proof/read-only checks. Applied000–036 are frozen. `.gitattributes` preserves037
bytes. Review approval applies only to the exact file and attested local target.

SQL checks use rollback-only synthetic users/declarations and existing native
reports. SET ROLE proves SQL ACL behavior, not fresh JWT issuance. Primary-only
positive registration is reported explicitly if the upgrade DB has no uploads.
