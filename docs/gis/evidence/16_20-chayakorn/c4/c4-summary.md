# C4 สำรวจแพ็กเกจ LDD 76 จังหวัด (สัปดาห์ที่ 3 งานเพิ่มเติม)

จัดทำ 18/11/2569 (แก้ไขรอบ 2) โดยชยากร · อ่านอย่างเดียว: อ่าน ZIP รายจังหวัดผ่าน `zipfile` ของ Python ไม่แตก ZIP รายจังหวัด ไม่แก้ข้อมูล ไม่ได้นำเข้าผ่านเว็บ ไม่ได้แตะ T0 · ใช้ฟังก์ชันของระบบจาก clone ที่ `7501cc8` · ผลเต็มใน `c4-ldd-inventory.csv` (77 แถว) · สคริปต์ `c4_inventory.py` และ `c4_outer_check.py` รันซ้ำได้โดยส่ง path เป็นอาร์กิวเมนต์

## 0. ที่มาของ ZIP รายจังหวัด
- สำรวจจาก **ZIP รายจังหวัดที่ผู้ใช้แตกออกจาก ZIP ภาคเอง** และวางไว้แยกโฟลเดอร์ตามภาค (ไม่ได้แตก ZIP ภาคในงานนี้) · กรุงเทพฯ ใช้ `Landuse_Bangkok_2566_.zip` (5,515,403 ไบต์ SHA256 `c3ef854c…ededdb8`)
- **ภาคกลาง ยืนยันแล้ว:** พบไฟล์ขนาด 555,825,522 ไบต์ในโฟลเดอร์ดาวน์โหลด (ชื่อ `zip.zip` ผู้ใช้ไม่ได้ระบุ path เอง พบจากการค้นด้วยขนาด) ขนาดตรงกับตารางของหัวหน้า · SHA256 `ed99291b51814efe56b2b22248cadebcd67f58244ab75a2aa903387a8cb0684e` · ZIP รายจังหวัด 25 ไฟล์ตรงกับ member ใน ZIP ภาค **ครบ 25/25 ทั้งขนาดและ CRC32** จาก central directory (ไม่ได้แตก) · ไม่มีไฟล์เกินหรือขาด (`c4-outer-check-central.txt`)
- **ภาคใต้ ภาคตะวันออกเฉียงเหนือ ภาคเหนือ ยังไม่ได้ยืนยัน:** ไม่พบไฟล์ขนาด 365,605,631 / 1,092,904,833 / 894,513,258 ไบต์ในเครื่อง จึงยังไม่ได้ยืนยันขนาด ZIP ภาคกับตารางของหัวหน้า และยังไม่ได้เทียบ ZIP รายจังหวัด 50 ไฟล์ของสามภาคนี้กับ ZIP ภาค · ตรวจซ้ำแล้ว: โฟลเดอร์ ZIP ที่ใช้สำรวจมีเฉพาะ ZIP รายจังหวัด (ภาคใต้ 14 · ภาคตะวันออกเฉียงเหนือ 19 · ภาคเหนือ 17) ไม่มี ZIP ภาคของ 3 ภาคนี้ จึงยังรัน `c4_outer_check.py` กับ 3 ภาคนี้ไม่ได้ สรุปคือ ภาคกลางยืนยันกับตารางของหัวหน้าแล้ว 25/25 ส่วน 3 ภาคยังไม่ได้ยืนยัน เพราะไม่มี ZIP ภาคในเครื่อง
- โฟลเดอร์ภาคตะวันออกเฉียงเหนือที่ได้รับสะกด "ภาคตะวันตะวันออกเฉียงเหนือ" ใน CSV ใช้ "ภาคตะวันออกเฉียงเหนือ"

## 2. ชั้นเขตการปกครองในแพ็กเกจ
- **มีชั้นจังหวัดและชั้นอำเภอครบ 41 จังหวัด** (ทั้ง 41 มีชั้นตำบลด้วย)

## 3. เพดานของการอัปโหลด
- **ผ่านเพดานทุกข้อ 7 จังหวัด:** กรุงเทพมหานคร นนทบุรี ปทุมธานี สมุทรปราการ สิงห์บุรี อ่างทอง ภูเก็ต
- **เกินอย่างน้อยหนึ่งข้อ 69 จังหวัด** แยกตามเพดาน (จังหวัดหนึ่งเกินได้หลายข้อ):

| เพดาน | จำนวนจังหวัดที่เกิน |
|---|---|
| ไฟล์ใดไฟล์หนึ่งใน ZIP > 20 MiB (`MAX_UPLOAD`) | 68 |
| ZIP > 20 MiB (ขนาดอัปโหลด) | 59 |
| รวมหลังคลาย > 80 MiB (`MAX_EXPANDED`) | 55 |
| อัตราขยาย > 100 (`MAX_RATIO`) | 2 (สมุทรสงคราม 104.42 · เพชรบุรี 107.24) |
| > 64 ไฟล์ (`MAX_MEMBERS`) | 0 |

- **`preflight_zip()` ของระบบเรียกได้** (import `gis_ldd_storage` จาก clone ได้โดยไม่ต้องเปิดระบบ) และเรียกกับทุก ZIP ที่อัปโหลดจริง: pass 7 · `GIS_LDD_ZIP_UNSAFE` 68 · `GIS_LDD_ZIP_NESTED` 1 (ลพบุรี) · `preflight_zip` ไม่ตรวจขนาด ZIP 20 MiB เอง (ระบบตรวจตอนรับไฟล์อัปโหลด) จึงใส่ค่าที่คำนวณเองไว้ในช่อง `preflight` ด้วย รูปแบบ `<ผลของระบบ>; caps=<เพดานที่เกิน>`
- 10 จังหวัดมี ZIP ไม่เกิน 20 MiB แต่ยังติดเพดานอื่น: ชัยนาท นครนายก พระนครศรีอยุธยา สมุทรสงคราม สมุทรสาคร ปัตตานี พัทลุง ยะลา ระนอง สตูล
- ใหญ่ที่สุด: ZIP 128,117,480 ไบต์ (นครราชสีมา) · ไฟล์เดียว 243,922,722 ไบต์ · รวมหลังคลาย 439,448,624 ไบต์

## 5. จังหวัดที่ผิดปกติ
- **ลพบุรี (ZIP ซ้อน ZIP):** ZIP ที่อัปโหลดคือ `ลพบุรีs.zip` (28,113,426 ไบต์ 2 member: `Landuse_ลพบุรี_2566(ปีล่าสุด).zip` และ `LUCODE.zip`) · ช่อง lu_layer ถึง amp_count อ่านจาก ZIP ด้านในในหน่วยความจำด้วย `zipfile` + `io.BytesIO` (ไม่แตกลงดิสก์): `LU_LRI_2566.shp` · 42,494 แปลง · `ldd-lu-text-v1` · UTF-8 · EPSG:32647 · ไม่มีชั้นจังหวัด/อำเภอ/ตำบล · ช่อง preflight และขนาดคิดจาก ZIP ที่อัปโหลดจริง: **`GIS_LDD_ZIP_NESTED`** (ข้อมูลอยู่ใน ZIP ซ้อน ซึ่ง preflight ของระบบปฏิเสธ) · caps zip>20MiB + member>20MiB
- **เพชรบูรณ์:** ระบบไม่รับรูปแบบช่องข้อมูล (หัวข้อ 4)
- **ยโสธรและสุโขทัย (EPSG ต่างจากจังหวัดอื่นในภาค):** อ่านกรอบพิกัดจาก header 100 ไบต์แรกของ `.shp` แล้วแปลงเป็นละติจูด/ลองจิจูดด้วย EPSG ที่อ่านได้ (rasterio) เทียบกับกรอบของจังหวัดเดียวกันใน `data/thailand.json`:
  - ยโสธร `EPSG:32647`: x 1,035,727..1,123,540 y 1,697,534..1,815,033 → ลองจิจูด 103.98..104.83 ละติจูด 15.30..16.34 · ระบบ Yasothon 104.00..104.83 / 15.29..16.35 → **สอดคล้องกับ EPSG ที่อ่านได้** (พิกัดใช้โซน 47 ต่อเลยขอบโซนไปทางตะวันออก)

  - ตรวจแบบเดียวกันทุกจังหวัด: สอดคล้อง 69 · ไม่สอดคล้อง 0 · เทียบไม่ได้ 7 (กรุงเทพฯ กาญจนบุรี ชัยนาท นครปฐม ชัยภูมิ เชียงใหม่ เพชรบูรณ์ เพราะ `NL_NAME_1` ในไฟล์ระบบผิดหรือซ้ำ จึงหากรอบของจังหวัดนั้นจากชื่อไทยไม่ได้) · พิกัดต่อเลยขอบโซนอีก 5 จังหวัด: จันทบุรี ตราด สระแก้ว (โซน 47) ชัยภูมิ เลย (โซน 48)

## 6. วิธีและเครื่องมือ
- **EPSG:** venv ไม่มี `pyproj` จึงใช้ **`rasterio.crs.CRS`** (rasterio 1.4.4 จาก requirements-native ใช้ PROJ เหมือนกัน) แทน ไม่ได้ติดตั้งอะไรเพิ่ม · ทุกจังหวัดได้ EPSG ไม่มี unknown · การแปลงกรอบพิกัดใช้ `rasterio.warp.transform`
- **preflight:** `gis_ldd_storage.preflight_zip()` ของระบบ **เรียกได้** (import จาก clone ได้ ไม่ต้องเปิดระบบหรือฐานข้อมูล) · ZIP ด้านในของลพบุรีส่งผ่านพารามิเตอร์ `open_read` ของฟังก์ชันเดียวกัน
- ฟังก์ชันระบบที่ใช้: `ldd_policy.select_land_use_layer`, `resolve_profile`, `horizontal_wkt` (ไม่มีจังหวัดใดที่ `select_land_use_layer` คืน None หลังเปิด ZIP ซ้อนของลพบุรี)
- ไม่ได้นับจุดพิกัดและไม่ได้อ่าน geometry (อ่านเฉพาะ header ของ `.shp`)
