## 4. สาเหตุ (จากการอ่าน ZIP และโค้ด อ่านอย่างเดียว)
### สมุทรสงคราม: อัตราขยายของ `.dbf`
- `LU_SKM_2568.dbf`: 11,081 แถว · ความยาวแถว 1,805 ไบต์ · 14 ช่อง · ช่องข้อความ (C) รวม 1,709 ไบต์ = **95% ของแต่ละแถว** มี 6 ช่องกว้าง 254 ตัวอักษร (`LU_CODE`, `LU_DES_TH`, `LU_DES_EN`, `LUL1_CODE`, `LUL2_CODE`, `LU_DES`) ซึ่งส่วนใหญ่เป็นช่องว่างที่เติมให้เต็มความกว้าง จึงบีบอัดได้มากผิดปกติ
- เทียบอ่างทอง: 9 ช่อง มีช่อง 254 อยู่ 4 ช่อง ความยาวแถว 1,102 ไบต์ อัตราขยาย 75.58 จึงผ่าน
- การตรวจอัตราขยายมี **2 จุด**: `green-area-backend/gis_ldd_storage.py` (`preflight_zip` บรรทัด 284–286, `MAX_RATIO = 100`) ตอนอัปโหลด และ `green-area-backend/gis_worker/ldd_provider.py` บรรทัด 189 (`ZIP_COMPRESSION_RATIO`, ค่า 100 เขียนตรง ๆ) ใน worker
- ข้อควรระวัง: `.dbf` นี้ขนาด 20,001,687 ไบต์ = **95.4%** ของเพดานต่อไฟล์ 20 MiB (`MAX_UPLOAD` / `MAX_MEMBER_BYTES` = 20,971,520) จังหวัดที่มีแปลงมากกว่านี้ราว 5% จะชนเพดานขนาดต่อไฟล์ต่อ แม้แก้เรื่องอัตราขยายแล้ว
- ขอบเขตของสมุทรสงครามใน `province_boundaries_ldd.json` เป็นแบบ `ldd-package` ที่สร้างจากแพ็กเกจเดียวกันนี้ (`package_sha256` = `b39404fa…`) ถ้าผ่านขั้นอัปโหลดได้ ขอบเขตน่าจะไม่ใช่ปัญหา (ยังไม่ได้พิสูจน์)

### อ่างทอง: ขอบเขตจังหวัดแบบหยาบ
- `province_boundaries_ldd.json`: อ่างทองเป็น `gadm-approx` ("GADM 4.1 level 1 as simplified … approximate") มีเพียง **169 จุด** ส่วนกรุงเทพฯ ที่ผ่านใน C2 เป็น `ldd-package` 1,841 จุด · ทั้งไฟล์มี `gadm-approx` 53 จังหวัด, `ldd-package` 24 จังหวัด
- `LU_ATG_2568.zip` ไม่มีชั้นขอบเขตจังหวัดมาด้วย (มีแค่ชั้นการใช้ที่ดินกับ ReadMe PDF) จึงสร้างขอบเขต `ldd-package` จากแพ็กเกจนี้ไม่ได้
- **ทำไมได้ Rejected (ยืนยันจากโค้ด):**
  - แต่ละแปลงที่ไม่อยู่ในขอบเขตจังหวัดทั้งแปลง จะถูกจัดชั้นโดย `boundary_tier()` (`ldd_policy.py:328-335`) จากบัฟเฟอร์ที่ `ldd_provider.py:472` สร้างรอบขอบเขต (`BOUNDARY_MINOR_M = 225` ม. และ `BOUNDARY_REVIEW_M = 1000` ม.) และ `ldd_provider.py:540-543`:
    - ทั้งแปลงอยู่ในบัฟเฟอร์ 225 ม. → `BOUNDARY_OUTSIDE_MINOR` (ข้อสังเกต) = 358 แปลง
    - ทั้งแปลงอยู่ในบัฟเฟอร์ 1,000 ม. **และ**ส่วนที่เลยบัฟเฟอร์ 225 ม. ไม่เกิน 5% ของพื้นที่แปลง (`BOUNDARY_REVIEW_PART_MAX = 0.05`) → `BOUNDARY_OUTSIDE_REVIEW_REQUIRED` (ต้องตรวจสอบ) = 25 แปลง
    - นอกนั้น → **`OUTSIDE_PROVINCE`** = 217 แปลง คือแปลงที่มีส่วนเลยบัฟเฟอร์ 1,000 ม. **หรือ**อยู่ใน 1,000 ม. แต่ส่วนที่เลย 225 ม. เกิน 5% ของแปลง (เงื่อนไขในโค้ดกว้างกว่า "เกิน 1,000 ม." อย่างเดียว)
  - `OUTSIDE_PROVINCE` อยู่ในกลุ่ม `FATAL` (`ldd_policy.py:124-126`) และ `outcome()` (`ldd_policy.py:141-150`) คืน `rejected` เมื่อมีรหัสใดที่ไม่อยู่ในกลุ่ม `REVIEW` จึงได้ **Rejected** แม้แปลงอื่นจะผ่าน
  - **พื้นที่นอกเขตรวม:** `ldd_provider.py:603-604` ใส่ `BOUNDARY_OUTSIDE_AREA_REVIEW_REQUIRED` เมื่อพื้นที่ส่วนที่อยู่นอกขอบเขต (รวมจากทุกแปลงที่ไม่อยู่ในขอบเขตทั้งแปลง) เกิน `DATASET_OUTSIDE_SHARE_MAX = 0.01` ของพื้นที่รวม **และ**เกิน `DATASET_OUTSIDE_MIN_M2 = 10,000` ตร.ม. · อ่างทอง 17,267,868.113 / 950,387,556.97 = **1.82%** จึงได้รหัสนี้ 1 ครั้ง (ระดับต้องตรวจสอบ ซึ่งอยู่ในกลุ่ม `REVIEW`) แต่ไม่ใช่ตัวที่ทำให้ Rejected
  - `geometry_error_count` 242 = 217 + 25 แปลงที่มีปัญหาขอบเขต
  - **ขอบเขตที่ใช้:** `ldd_provider.py:623` ใส่ `BOUNDARY_APPROXIMATE` เมื่อแหล่งขอบเขตไม่ใช่ `ldd-package` (อ่างทองเป็น `gadm-approx`) ส่วนจังหวัดที่เป็น `ldd-package` ได้ `BOUNDARY_FROM_DATA_PRODUCER` เหมือนกรุงเทพฯ ใน C2
- ไฟล์ขอบเขตถูกปัก sha ไว้ใน `ldd_provider.py:34` (`BOUNDARY_LDD_SHA256`) และ migration 051 (บรรทัด 25) จึงเปลี่ยนไฟล์เองไม่ได้ ต้องมี migration ใหม่
