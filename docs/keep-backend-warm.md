# กัน backend หลับ (Render free plan)

## ปัญหา

`green-area-backend` รันบน Render **free plan** ซึ่งพักเครื่องเมื่อไม่มีคำขอเข้ามาราว
15 นาที คำขอถัดไปต้องรอปลุกเครื่องก่อน

วัดจริงเมื่อ 13 ก.ย. 2569:

| สิ่งที่วัด | ผล |
|---|---|
| `/health` คำขอแรกหลังหลับ (ครั้งที่ 1) | ไม่ตอบเลยจนครบ timeout 180 วินาที |
| `/health` คำขอแรกหลังหลับ (ครั้งที่ 2) | HTTP 200 — first byte ที่ **47.2 วินาที** |
| `/health` หลังเครื่องตื่นแล้ว | 0.12–0.13 วินาที |
| DNS + TCP + TLS | รวม 0.078 วินาที (เครือข่ายไม่ใช่ปัญหา) |

ฝั่งเว็บมีป้าย "กำลังปลุกเซิร์ฟเวอร์ อาจใช้เวลาประมาณ 1 นาที" กับ timeout 90 วินาที
แล้ว (ดู `green-area-frontend/src/utils/fetchRetry.js`) — เอกสารนี้ว่าด้วยการทำให้
**ไม่ต้องเจอการรอตั้งแต่แรก**

## ทางเลือก

| วิธี | ความน่าเชื่อถือ | ตั้งค่าที่ไหน | ค่าใช้จ่าย |
|---|---|---|---|
| **A. GitHub Actions cron** (มีในรีโปแล้ว) | ปานกลาง — cron ช้าได้ 10–30 นาที | ในรีโป | ฟรี |
| **B. UptimeRobot / cron-job.org** | **สูง** — ตรงเวลาจริง | เว็บภายนอก | ฟรี |

| **D. Vercel Cron** | สูง | `vercel.json` | แผน Hobby ยิงได้ **วันละครั้ง** เท่านั้น — ไม่พอ |
| **E. อัปเกรด Render เป็น Starter** | สูงสุด — ไม่หลับเลย | Render | ~$7/เดือน |

**คำแนะนำ:** ใช้ **A + B คู่กัน** · A อยู่ในรีโปจึงติดไปกับโค้ดและตรวจสอบย้อนหลังได้
ส่วน B เป็นตัวที่พึ่งได้จริงเรื่องเวลา · ถ้าเป็นงานที่พลาดไม่ได้ (วันสอบ/นำเสนอ) ให้
**กดปลุกเองล่วงหน้า** ด้วย (ดูท้ายเอกสาร)

## ⚠️ ข้อควรระวังเรื่องโควตา — อ่านก่อนเปิดใช้

Render free plan ให้ **750 ชั่วโมงเครื่องต่อเดือนต่อบัญชี**

- 1 เดือน ≈ 730 ชั่วโมง → ปลุกตลอด 24 ชม. กินเกือบเต็มโควตาของ **service เดียว**
- ถ้ามี free service มากกว่าหนึ่งตัวในบัญชีเดียวกัน **จะเกินโควตา** แล้วโดนระงับ

ถ้าไม่อยากเสี่ยง ให้ยิงเฉพาะช่วงที่มีคนใช้จริง เช่น 07:00–22:00 น. ไทย
(= 00:00–15:00 UTC) แก้บรรทัด cron ใน `.github/workflows/keep-backend-warm.yml` เป็น:

```yaml
- cron: '*/10 0-15 * * *'
```

15 ชั่วโมง/วัน ≈ 456 ชั่วโมง/เดือน — ปลอดภัยกว่ามาก

## A. GitHub Actions (ไฟล์พร้อมแล้ว ต้องตั้งค่า 1 อย่าง)

ไฟล์: `.github/workflows/keep-backend-warm.yml` — ยิง `/health` ทุก 10 นาที

**ต้องทำก่อนถึงจะทำงาน** — ตั้งตัวแปรบอก URL:

1. เปิด repo บน GitHub → **Settings**
2. **Secrets and variables** → **Actions** → แท็บ **Variables**
3. **New repository variable**
   - Name: `BACKEND_HEALTH_URL`
   - Value: `https://green-area-backend.onrender.com/health`
4. กด **Add variable**

> ใช้ *variable* ไม่ใช่ *secret* เพราะเป็น endpoint สาธารณะ ไม่ใช่ความลับ — และการ
> เห็นค่าในล็อกช่วยตอนดีบั๊ก · ที่ไม่ hardcode ลงไฟล์เพราะ URL ของ Render
> เปลี่ยนได้ถ้าย้าย service

**ทดสอบว่าใช้ได้:** แท็บ **Actions** → *Keep backend warm* → **Run workflow**

ข้อจำกัดที่ต้องยอมรับ:
- cron ของ GitHub เข้าคิวรวมทั้งแพลตฟอร์ม **ช้าได้ 10–30 นาที** ในชั่วโมงเร่งด่วน
  ซึ่งเกิน 15 นาทีที่ Render ใช้ตัดสินใจพักเครื่อง
- workflow ตามตาราง **ถูกปิดอัตโนมัติเมื่อ repo เงียบ 60 วัน** (GitHub จะส่งเมลเตือน
  ก่อน กดเปิดใหม่ได้ที่แท็บ Actions)
- รันจาก **default branch** เท่านั้น

## B. UptimeRobot (แนะนำให้ทำเพิ่ม — ตรงเวลากว่า)

ฟรี 50 monitors ยิงได้ทุก 5 นาที และได้ระบบแจ้งเตือนเวลาเว็บล่มแถมมาด้วย

1. สมัคร/เข้าสู่ระบบที่ <https://uptimerobot.com>
2. **+ New monitor**
3. กรอก:
   - **Monitor type:** `HTTP(s)`
   - **Friendly name:** `GreenLens backend`
   - **URL:** `https://green-area-backend.onrender.com/health`
   - **Monitoring interval:** `5 minutes`
4. (ควรทำ) **Advanced** → ตั้ง **Timeout** เป็นค่าสูงสุดที่ตั้งได้ เพราะคำขอปลุก
   เครื่องกินเวลาเป็นสิบวินาที ถ้า timeout สั้นจะขึ้นว่า "down" ทั้งที่แค่กำลังตื่น
5. (ถ้าต้องการ) ใส่อีเมลรับแจ้งเตือนเวลาเว็บล่มจริง
6. **Create monitor**

ทางเลือกที่เทียบเท่า: <https://cron-job.org> (ตั้งความถี่ได้ละเอียดกว่า ตั้ง timeout
ได้ถึง 300 วินาที) หรือ Better Stack

## ปลุกเองก่อนใช้งานจริง (วันสอบ/นำเสนอ)

ยิงคำสั่งนี้ล่วงหน้า **2–3 นาที** ก่อนเปิดเว็บให้คนอื่นดู:

```bash
curl -m 180 https://green-area-backend.onrender.com/health
```

ได้ `{"ok":true}` เมื่อไหร่แปลว่าเครื่องตื่นแล้ว · ถ้าคืนเร็ว (< 2 วินาที) แปลว่า
ตื่นอยู่แล้ว · หรือกด **Run workflow** ในแท็บ Actions ก็ได้ผลเดียวกัน

จากนั้นเปิดเว็บทิ้งไว้ — ตราบใดที่มีคนใช้ เครื่องจะไม่หลับ

## หมายเหตุ: การปลุกไม่ได้แก้ทุกอาการช้า

การ ping แก้ได้เฉพาะ **cold start** เท่านั้น ยังเหลืออีกสาเหตุที่ทำให้รอนาน คือ
**อำเภอที่ยังไม่มีในแคช** — backend ต้องคำนวณสดจาก Google Earth Engine (~6–40
วินาทีต่อรายการ) และหน้าอำเภอยิงพร้อมกัน 4 เส้น

สถานะแคชระดับอำเภอ: NDVI ครบ 928 แล้ว · **LST ยังค้างราว 196/928** อุ่นต่อได้ด้วย

```bash
cd green-area-backend
python prefetch_cache.py --layer district-lst --years 2025
```

ใช้เวลาราว 1.5–2 ชั่วโมง รันซ้ำได้ ถูกฆ่ากลางทางแล้วรันต่อได้ไม่เสียงานเดิม
